# Repository review — 2026-09-17

Marchlands has a working first vertical slice: citizens, physical logistics,
construction, farms, household meals, emergent roads, upgrades, and saves are
connected and exercised by scenarios. The separation of production, workforce,
stores, and population makes the simulation reasonably navigable. Military,
institutions, rail, and rival kingdoms remain outside the implemented slice.
The next useful investment is reliability at state transitions and playtesting
the existing loop.

The checkout already contained asset, validator, shader-probe, and simulation
changes. Those were preserved; this review tested the resulting working tree.

## Fixed in this pass

- **Gatherers worked from home after sleeping.** Nighttime replaces their route
  with the walk home, then clears it. Gathering interpreted the cleared route
  as arrival at the resource. It now reestablishes the resource destination
  before starting work.
- **Expired orders stayed on the job board.** Gathering and felling orders for
  depleted resources were released for another worker to claim indefinitely.
  Invalid orders now retire; the same treatment applies to hauling with a
  missing endpoint and harvesting with no remaining fields. Reachability
  failures still release valid work for someone else.
- **Paused saves inherited the wrong resume speed.** The pause state survived,
  but its remembered speed came from the session being replaced. Saves now
  include the resume speed. Older saves remain readable, with normal speed as
  the fallback for an older paused save. Pausing through `set_speed(0)` also
  remembers the current rate.
- **HUD sizing generated a startup warning.** The root control now uses equal
  anchors with the existing explicit viewport sizing. Its narrow-window layout
  and building selection were verified under Xvfb.
- **The save/load scenario could fail after successful construction.** Its
  instantaneous worker-count assertion failed when the house was already
  complete. It now checks progress and eventual completion of the specific
  building ordered after loading. A negative control confirms an untouched
  construction site fails the new assertion.

The focused regressions reproduced the gathering, expired-order, and paused-save
defects before their fixes. Run them with:

```bash
tools/godot_env.sh --headless --path game --script res://tests/regressions.gd
```

## Follow-up: all three priorities completed

1. **Save validation and safe replacement.** New schema checks cover typed
   records, finite bounded quantities, entity IDs, reciprocal assignments,
   resource inventories, construction, terrain, wear and assets. Object decoding
   is disabled. Restoration builds a separate world and simulation, checks node
   counts and capacities against the seed, and replaces the active march only
   on success. Invalid data leaves the world, clock, camera, selection and
   placement controls intact. Writes also validate their snapshot and compare
   the complete read-back before replacing the previous save.
2. **Detailed persistence checks.** The harness snapshots live state independently
   of the writer and compares exact quantities and structured records. It now
   covers household food, individual hunger/meals, construction deliveries and
   costs, terrain edit contents, full wear arrays, resource history, positions
   and ID counters. Positions allow at most 0.1 mm of transform noise.
3. **Current asset documentation.** The README now describes actual height,
   bounds, attachment and LOD checks; obsolete collision-export claims are
   removed. It retains the real limitations around accessor metadata, topology,
   origin tolerances and silhouette checks.

The stronger checks found additional defects, all fixed: restoring objects
recomputed elevations after later earthworks; tiny carried loads were dropped;
reordered records inflated future IDs; explicitly empty farm layouts generated
new fields. Successful loading also clears the old road-extent cache. New
immigrants are clamped inside the map, while older saves with arrivals just
outside a corner remain readable.

Focused verification: **95 malformed-save cases rejected with zero failures**,
including unsafe finite numeric extremes and all staged-world rejection paths;
**43 fingerprint checks passed**, including deliberate mutations and real disk
round-trips. Current and older version-1 saves, unfinished upgrades, arrivals,
empty farms and reordered records are covered. The object-decoding test emits
explicitly marked expected engine errors. All ten simulation scenarios listed
above and the original regression runner were rerun after these fixes and passed.
Run the two new suites with:

```bash

tools/godot_env.sh --headless --path game --script res://tests/save_fingerprint.gd
```

A rendered save/load check under Xvfb also passed the detailed round-trip,

the main viewport (`artifacts/save_hardening_viewport.png`). Loading briefly
holds both worlds in memory; validation is not a resource-exhaustion sandbox
