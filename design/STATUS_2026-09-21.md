# Integration review and remaining work — September 21, 2026

This is the current handoff. Earlier dated reports describe their own stages;
their smaller test counts and narrower feature lists are historical.

## What was left unfinished

The accumulated work was present in the working tree but had never been
committed. Local and remote `main` still pointed to `6407510`, the original
household-meals implementation. This integration packages the fixes, generated
assets, gameplay systems, tests and CI together.

One correctness defect emerged during this review: destroying a bridge moved
a lost cart's visual model to safety but left its authoritative cargo position
over the vanished deck. Workers could not recover it, and saves retained the
wrong position. The fix moves the cargo record and recovery orders along with
the cart, clears a claimed worker's old route, and preserves goods and permanent
population loss. A regression checks the saved location and real recovery.

CI also omitted the newer society, trade and bridge screenshot directories
from uploaded evidence. Those directories are now included. Release dependency
review found no missing source assets or resource files; the pinned engine
checksum and action revisions match their official releases.

## Implemented scope

| Request | Current behavior |
| --- | --- |
| Markets and emergent roads | Vendors move actual food, households collect it, and their movement creates paths. |
| Research-based roadwork and extent choices | Paid improvements require research; roughly 20%, 50% or all of the connected network can be selected. Prices depend on the cells actually improved. |
| Terrain/deposit readability and speed controls | Northern backdrop/seabed and camera clearance are covered; deposits have inspection text and distinct iron presentation. Speeds are pause, 1×, 2×, 4×, 16×, 32× and 64×. |
| One simulated rival and combat | Seeded personality, developer editing, finite growers/guards, burning buildings, swords and firepots, supplied units, huts and forts. The rival does not expand its town. |
| Soldiers drawn from citizens | Recruitment reassigns an existing person. Recruiting every civilian leaves no production workforce. Discharge preserves identity, equipment and injuries. |
| Visible injuries and researched armor | Discrete body regions, wounds, severed limbs and armor layers affect combat/work. No health bars. This is a body-region model, not anatomical physics. |
| Cattle and leather chain | Physical domestication, discovery, ranching, breeding, slaughter, hides, tanning and paid armor production. |
| Citizen caravans | Physical loading, provisions, barter, return and unloading; repeat/recall, route wear, death and cargo recovery. |
| Map sizes and crossings | Four sizes from 768 m to 6,144 m, geographic rivers/ridges/passes/forest stands, paid worker-built timber bridges and saved world dimensions. |

The earlier **baker/bread idea is not implemented**. Food remains a shared
resource produced by farms and livestock; markets distribute it. A grain,
flour and bread chain would be new work, not a missing file or half-written
system recovered by this merge.

## Remaining priorities

1. **Make trade worth sustaining.** The neighbor starts with 32 iron: four
   ordinary trades, then stock is exhausted. Playtest whether a bridge repays
   its cost. If recurring trade is the next goal, give the neighbor physical
   export production and useful recurring demand rather than free restocking.
2. **Broaden generated-world tests and playtesting.** The complete paid
   crossing/trade/save scenario uses one Small-world seed. Larger-world tests
   cover geography, distant navigation, crossing hooks, openings and saves.
   Run complete economies/trade journeys across multiple seeds and sizes, and
   add an explicit check that starting resources are sufficiently reachable.
3. **Measure a busy XL game.** Existing GPU measurements cover terrain and
   resources, not a populated settlement at 32×/64×. Measure long sessions,
   actual travel pacing, growing populations and save/load memory peaks before
   claiming large-world performance is finished.
4. **Improve the first-session feedback.** Default startup retains the legacy
   landscape; World creates the river geography. Help players discover that
   flow and make arriving imports and stalled trade easier to understand.
5. **Choose the next base feature deliberately.** Scouting/discoveries or the
   baker/food chain are candidates. Avoid adding more upgrade tiers before the
   existing economic and geographic choices are rewarding.

Explicitly deferred ideas include automatic escorts, caravan stops/waypoints,
more civilizations, negotiated prices/diplomacy, medicine/prosthetics, bandits,
boats and weather. Larger maps currently contain one nearby trading rival,
not additional towns. These features have not been silently counted as done.
